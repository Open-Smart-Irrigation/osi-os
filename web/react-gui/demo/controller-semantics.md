# Public simulator controller semantics

This file records the recovered simulator contract and the current-main reconciliation. The imported historical contract is not present in this checkout; use [the action inventory](action-inventory.md), [the stage-one review](port-sol-review.md), and the source-linked tests as the trace map.

## Controller semantics: shipped rules and public simulation

The following source distinctions are deliberate. The simulator reuses deterministic decisions where they exist, and records its local representation of radio/hardware timing. It does not claim that a browser model proves behaviour of a physical valve.

### Clock and seed

Public epoch is `2026-10-10T02:59:50.000Z`, ten seconds before06:00 in Africa/Kampala. Presentation epoch is unchanged. Keep two named seed zones; first starts expanded. Seed all catalogue channel families needed for the inventory, including a STREGA valve in each zone, dry SWT in the first and wet SWT in the second, a dendrometer cohort, rain/flow sources and fictional gateway observations. The two zones' trigger configurations start disabled so a visitor controls first activation. Deterministic sample baselines: first zone SWT1/2/3 are45/50/55kPa; second zone10/12/14kPa; these are explicitly fictional measured samples, not fallbacks for missing data. Retain deliberate missing rows/channels/days. Use30-minute synthetic sensor intervals by default, overridable by supported device interval settings; seed90 calendar days through the epoch and append thereafter. Newly added devices begin with creation-time readings plus clearly fictional historical demonstration data tagged as such, using the same deterministic generator.

One queue stores `{atMs,priority,sequence,id,deviceEui?,generation,callback}`. Advance processes every due event at its own timestamp before setting the final target time. Invalidate by entity generation on remove/reset/config replacement; stale closures must not close a later command. Equal-time order is: elapsed flow integration up to boundary; automatic/service closures and cancellation completion; command/plan acknowledgements; sensor samples and completed delayed soil responses; local-date scheduler-status rollover; plan starts; daily trigger evaluation; derived-summary invalidation. Stable sequence breaks remaining ties. User writes at current time drain existing due events first. Time never goes backward, and each event ID executes once.

Speed is1/10/60 as existing protocol. Browser performance.now drives elapsed real time; overridden Date.now/new Date expose simulated time only in app document. Pause/hidden tab means no catch-up elapsed time. Resume resets last real tick. Reset returns all clocks/counters/state to seed. `advanceTo(targetMs)` handles arbitrary forward test jumps. Runtime batches processing without skipping events; UI remains responsive for90-day test jumps. `jumpToNextEvent()` targets earliest meaningful ACK/closure/plan/daily-trigger/service/delayed-soil event within 8 days. Routine samples and day buckets are processed on the path but are not user jump targets. No meaningful event returns false and a localized no-event status; pause stays unchanged. With disabled triggers/no plans/commands, routine sampling alone does not make next-event jump forever.

Synthetic local ACK delay is2 simulated seconds; reboot/identify/calibration lookup completion5 seconds; soil response begins10 simulated minutes after observed irrigation. These are demonstration constants, not radio guarantees. A one-minute manual open commanded at t has observed open at t+2s and close at t+62s; expectedCloseAt is the simulated known closure. This intentionally does not reproduce the edge's120-second downlink uncertainty budget in FLOW `write-strega-expectation`. Ledger volume integrates from observed open only: rate6L/min for seed flow source gives6L over60 observed seconds. Early close integrates only elapsed observed duration. Soil response is a deterministic bounded decrease in SWT and increase in available VWC channels proportional to delivered net mm, followed by ordinary gradual drying; null/missing channels remain null. Calibration and interval changes apply only according to their specified historical rules, not by rewriting every historical sample.

### Weekly and one-time plans

Pinned sources: `EDGE/osi-valve-control/plan.js` `validateScheduleInput`, `compileWindows`, `nextLocalOccurrence`, `nextRun`; `api.js` schedule CRUD and scheduler-status branches; `push.js` `compileAndQueue`; `workers.js` `runOnceTick` and skip-date reset. Existing `plan.test.js`, `api.test.js`, `workers.test.js` are parity references and should be executed as pure/local source tests where possible.

Weekly duration integer1..1439; weekdays mask1..127 (bit0 Sunday); start time strict HH:MM; label string capped80. Disabled/deleted rows do not compile. Maximum4 windows/day. Overlap uses half-open windows: equality at end/start is allowed; a window crossing midnight conflicts with a next-day window beginning before its spillover end, including Saturday→Sunday. Validation happens before mutation. The compile response carries seven arrays of onH/onM/offH/offM/scheduleUuid/label. GEN1 weekday delivery and GEN2 grouped daymask delivery follow `push.js`/`plan.gen2Groups`; do not claim all seven days changed for every save. Public ACK is always deterministic success in ordinary flows; tests may inject failure to prove resend recovery. ONCE changes never send/clear weekly plans.

A delivered WEEKLY plan is represented as an autonomous on-valve window: it opens exactly at the compiled local start instant and closes exactly at its compiled end, without a second 2-second command-open delay. Reuse the irrigation state/ledger lifecycle with zero opening delay for this source. The 2-second plan-delivery ACK is separate and must complete before that window starts; a window whose current generation is still undelivered at start records SKIPPED/plan_not_delivered and is not replayed after later ACK. Later windows can execute after delivery. This is deterministic local delivery modelling, not radio reliability parity. At a shared boundary close runs before the next start, so adjacent windows both execute and measured volume is continuous without overlap. A changed/resending plan generation cannot receive an obsolete ACK.

Timezone is stored on the schedule at creation (`device.zone_timezone || gatewayTimezone || 'UTC'`) as in `api.js`; current valve display fallback is zone→gateway→UTC. `plan.nextLocalOccurrence` iterates calendar days, snaps spring gaps to the first real local minute, and picks one deterministic fall-back occurrence using the day's noon offset. Reuse/port these pure calculations with pinned parity cases rather than UTC24-hour arithmetic. No event is replayed after resume. Skip-today date is evaluated in valve timezone; once local date passes the stored date, status returns ACTIVE. Scheduler status controls the on-valve WEEKLY plan. Shipped `runOnceTick` does not consult scheduler_status; a pending enabled ONCE still fires while WEEKLY is deactivated. Explain this existing distinction in the simulation guidance and test it.

ONCE duration integer1..255; fire_at parses as ISO instant and normalizes to UTC. At execution, elapsed lateness <=10min may dispatch, >10min produces SKIPPED/one_time_missed. Normal chronological time advance evaluates at the due instant, so a large advance does not falsely miss a plan. The overdue case is for a plan created/re-enabled with a past time. Preserve PENDING→FIRED and dispatch PENDING→ATTEMPTED→SENT, with a unique schedule/fire marker preventing duplicate emission on retries. Delete/disable before event prevents dispatch; completion does not re-arm the same schedule. Synthetic ACK completes command observation; it does not reset once_state.

### Cancellation and service actions

`EDGE/osi-valve-control/cancel.js` distinguishes queue cancellation from an already-running valve. In the public model, pending cancellation prevents future acknowledgement/open and marks the pending expectation CANCELLED. A running actuation returns 409 with outcome `already_running`; its record and physical simulated flow remain unchanged until its timer or an explicit operator close. Cancellation never fabricates `observedCloseAt`. The ordinary tile offers queued cancellation; early close is the existing two-step settings override (`ValveSettingsDialog.handleClose`). Delete-device is an explicit public-simulator recovery rule that stops synthetic water and pending events while retaining the historical record.

Partial opening/flushing are one-shot service actions, not stored percentages; source `workers.js` service-action classification and `ValveServiceDialog`. Public representation: OPEN partial sets physical openness to the requested percentage after2s, CLOSE partial reduces current openness by that percentage (floor0), with flow scaled by resulting fraction; no automatic close is invented for this action. Flushing uses requested percentage for5s then returns to100% or0% according to returnPosition. Timed service OPEN uses selected seconds/minutes/hours amount then closes; timed CLOSE represents closed hold for that duration then returns to prior openness. These hardware movement details are explicit illustrative simulator behavior: the source client specifies commands and labels, not a full hydraulic motion model. Record source `service_action` and allow override close/reset so the visitor can recover.

### Current-main reconciliation (stage 1)

The historic simulator contract below records the imported 26fe14d59 candidate. For this port, current-main edge behavior and Sol's review govern where they differ:

- Legacy zone schedules still evaluate once at the flow's daily 06:00 opportunity. Keep source-linked eligibility and debounce. A sensor threshold crossing alone does not dispatch.
- Conditional irrigation is separate. The public model reports `qualification.qualified: false` with `qualification_unavailable`; an enabled conditional schedule returns 503. The legacy daily path stays available independently.
- Ordinary timed opens retain the edge acceptance behavior. A second open while a timed run is active is ignored by the valve and cannot replace its original timer. If the valve was opened externally, an ignored timed open creates no modeled run or close timer. The oracle is `scripts/test-valve-v081-equivalence.js`.
- Timed-close holds still reserve the valve. A normal timed run closes at its own original duration; early close uses the existing settings override. Do not convert timed-close behavior into an unqualified bare `CLOSE`.
- Current-main route dispositions for policy, rain-source, scheduler, service and user routes are recorded in `route-dispositions.ts`; tests cover the supported and unsupported boundaries. The dashboard's rain-source GET returns an edge-shaped read-only view derived from demo assignments; rain-source writes remain unsupported.

The historic candidate's manual-busy refusal is superseded. An ordinary repeated timed open is accepted and ignored by the valve; it does not reset a run timer or create a timer for an externally opened valve. Daily trigger dispatch also skips a valve whose current state is OPEN without a simulator-owned active command. Timed-close holds still refuse a competing open.

### Automatic irrigation

The existing flow's daily injector uses cron `00 06 * * *`; the public model interprets its simulated gateway process timezone as `gatewayTimezone`. The flow's zone and measurement queries select the eligible device; its decision node evaluates once each day. This is a daily 06:00 evaluation, not a threshold test on every sensor sample. Use the oldest-created eligible STREGA in the zone as that query does; no assigned STREGA means `missing_valve`. Disabling or deleting the schedule prevents evaluation. Under the seeded `scoped_access=false` persona the scope-holder interlock does not apply; do not remove it from production.

SWT inputs include KIWI_SENSOR, TEKTELIC_CLOVER, DRAGINO_SDI12, and Chameleon-enabled DRAGINO_LSN50; all rows linked to WATERMARK evidence are excluded. Use points recorded at or after now−1h. SWT1/2 use canonical value then legacy swt_wm1/2 aliases; SWT3 uses canonical only. SWT_AVG first averages each row's non-null channels, then averages those row means, exactly as the SQL expression; do not weight devices equally or count missing channels as zero. No valid points means no_data_last_hour. Mean >= threshold irrigates (equality matters), lower mean skips. Basic duration clamp1..240 applies. `sameLogicalWindow` debounces by UTC calendar date, not farm date: a second attempt the same UTC day cannot open again. Frontend offers SWT1/2/3/AVG and DENDRO only. VWC is a planned TypeScript enum member without a native tab; do not invent a VWC trigger UI or silently run it as SWT1.

DENDRO dispatch follows the current FLOW node `Decide + build actuator cmd + build DB logs` (`5f0d2b7e9b9b1b3a`). A fresh nonempty recommendation action dispatches at the daily opportunity; the saved threshold and `response_mode` do not gate this executor. Durations use action factors: `decrease_20` 0.8, `decrease_10` 0.9, maintain actions 1, `increase_10` 1.1, `increase_20` 1.2, and `emergency_irrigate` 1.5, rounded and clamped to1..240 minutes. Local recommendations are rejected when their timestamp is invalid or more than36 hours old; the flow's age-only check permits a future local timestamp. A server-preferred recommendation uses the shared bundle receive time, accepts the exact six-hour boundary and rejects a future or older bundle. In this offline simulator there is no cloud bundle input, so daily evaluations use the selected local recommendation; the selection helper and source-flow VM probe pin both source boundaries. Cadence, freshness handling and UTC-day debounce remain in place; no sensor-sample threshold crossing dispatches immediately. `response_mode` remains an accepted schedule field for API compatibility but is not used by this executor.

The source does not implement a complete cross-source arbiter: WEEKLY runs on hardware while edge ONCE and daily trigger paths can dispatch independently. The public model gives each valve one active run owner. Planned or automatic starts that collide with an existing owner are recorded as skipped and are not replayed; a repeated manual timed open follows the current valve contract and is accepted without changing the existing run. A timed-close hold refuses a competing open. At equal time, closure precedes new starts, so adjacent windows execute. This is an illustrative model rule, not physical overlap parity. C36 covers manual→weekly, weekly→trigger, ONCE→trigger, and two same-time automatic starts; one flow interval is credited, never doubled.
