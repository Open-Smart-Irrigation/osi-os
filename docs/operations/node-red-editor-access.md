# Node-RED editor access on a gateway

The shipped `settings.js` sets `httpAdminRoot: false`, so the Node-RED editor
and admin API are closed on every gateway (`AGENTS.md`, "Security"). This page
holds the follow-on notes that moved out of `AGENTS.md` on 2026-10-22; it
carries the same authority.

## What stays open and what else closes

`httpStatic`/`httpStaticRoot` (`/gui`) and every HTTP-node product route are untouched — they share the listener but are a separate Express mount. `feeds/chirpstack-openwrt-feed/apps/node-red/files/node-red.nginx`'s `/apps/node-red` location returns 404 instead of redirecting to the now-closed editor. Operator smoke check after a restart: `scripts/smoke-node-red-admin-off.sh` (loopback only; not run in CI, no live Node-RED runtime exists in this repo).

## Re-enabling the editor for field repair

Re-enabling the editor is a deliberate operator action, not a config default: edit the deployed `/srv/node-red/settings.js` on the gateway (set `httpAdminRoot` back to its Node-RED default, or comment the line out) and restart Node-RED, then close it again before leaving the gateway. There is no in-repo toggle for this by design — it forces an operator to be at (or SSH'd into) the gateway rather than exposed on the network.

## Durable fix, not yet built

Per-device `adminAuth` with one bcrypt hash generated by `node-red.init` on first boot into a root-owned, mode-0600 credential file, distinct from `AUTH_TOKEN_SECRET`. Tracked as a follow-up; see the PR that introduced `httpAdminRoot: false` for the full design and the three-route regression it still needs (`/gui` succeeds unauthenticated, `GET /flows` returns 401, authenticated `GET /flows` succeeds).
