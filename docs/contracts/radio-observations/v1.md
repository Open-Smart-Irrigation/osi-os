# Radio observations v1 implementation contract

Frozen for the first implementation slice, 10 September 2026. Uses history sync protocol/hash v1. Additive radio registration must preserve every existing table's hash fixtures.

## Row and identity

Table `radio_uplinks`, cursor `id`, history key `RADIO_UPLINK|<gatewayEui>|<id>`, segment `<deveui>|<UTC date>`. Canonical columns in this order: `id INTEGER`, `installation_uuid TEXT`, `deveui TEXT`, `recorded_at TIMESTAMP`, `deduplication_id TEXT`, `metadata_json JSON`.

`id` is a positive safe integer never reused within a gateway's radio store lineage. `installation_uuid` matches canonical edge installation identity. Metadata is a JSON object, version 1, without raw payload or credentials. Canonical history JSON encoding uses the existing helper, not a new hash algorithm.

Metadata fields:

- `version: 1`, `ingested_at: UTC timestamp`, `timestamp_source: network|ingest`, `deduplication_uncertain: boolean`.
- `radio`: nullable `frequency_hz`, `spreading_factor`, `bandwidth_hz`, `coding_rate`, `f_cnt`, `adr`, `f_port`. Numbers must be finite and integer where applicable.
- `reported_position`: null or `{latitude, longitude, altitude_m, accuracy_m, hdop, satellites, fix_time, source}`. Coordinates bounded WGS84; unknown optional fields null.
- `receivers`: sorted array, max 64 entries. Each has `gateway_id`, nullable nonnegative safe-integer `uplink_id_num`, nullable finite `rssi_dbm`, `snr_db`, `channel`, `crc_status`, and `position` (null or gateway fix snapshot with coordinates, fix_time, source, sync_version). It is not a second editable gateway location store.
- `device_location`: null or confirmed-location snapshot including revision UUID, coordinates and effective time; zone fallback must carry provenance `zone_fallback`.

All fields above are explicit, not inferred zeros. Maximum serialized metadata 64 KiB. Receiver order is gateway ID then receiver ID, null before numeric. Native receiver key is gateway ID plus numeric ID or null sentinel within the parent. Duplicate identical receivers collapse; conflicting same-key records reject normalization with a visible diagnostic rather than average or silently choose. Same event with a newly supplied distinct receiver merges and dirties the parent. Native deduplication ID scopes to installation; without it assign a persisted UUID and mark uncertain. Do not deduplicate by frame counter.

## Local store and adapter

Canonical module `osi-radio-helper` exposes `normalizeUplink(event, context)`, `createRadioStore(options)`. Context supplies validated installation UUID, ingest time and known receiver/device positions; no environment reads inside normalization.

Store supports asynchronous `capture(row)`, `all(sql,params)`, `bridgeDirty(farmingDb)`, `status()`, `close()`. `all` is an internal trusted SQL adapter only, not an HTTP interface. Capture, parent receiver merge and dirty generation commit together in radio.db. Dirty transfer into farming history ledger is idempotent; generation compare prevents clearing newer corrections. Parent row reads are snapshot-coherent because receiver JSON is in the same row.

A farming.db radio-store identity marker and radio.db matching UUID guard first creation/restore. If marker exists and radio.db is missing or mismatched, fail closed with a recovery-required status; never recreate and reuse old IDs. Installation recovery must be ACTIVE. Use a separate serial DB connection/queue and versioned/checksummed radio schema ledger. Capture default off via OSI_RADIO_CAPTURE_ENABLED. Initial budget 512 MiB plus filesystem free-space reserve; exceeding either pauses new capture, never prunes evidence.

The existing history worker uses the radio adapter only for source queries of this table; bookkeeping stays in existing cursors/dirty/quarantine/manifests. Unavailable/disabled radio must not break other table streams. No new batch route, ACK sequence or radio capability.

## Existing transport semantics

Preserve durable prefix semantics: validation quarantine can advance; hash/order and retryable failures stop. Unknown radio table cannot advance its cursor. Receiver correction reuses parent history key with a new hash. Respect server pacing fields.

## Acceptance vectors

One event with three receivers; reordered receiver input identical hash; null receiver-ID duplicate collapse and conflict rejection; unknown GPS stays null; native dedup replay no new row; late receiver marks dirty; capture crash and bridge crash replay; generation race leaves latest dirty; missing/mismatched radio store fails closed; budget pause leaves farming operations available; malformed radio followed by valid row quarantines without poisoning later rows; all eight existing history hash families unchanged.
