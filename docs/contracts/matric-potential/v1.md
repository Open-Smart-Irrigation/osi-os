# Matric potential conversion, hPa convention v1

Use this conversion for every matric-potential sensor. Canonical soil water tension remains a positive kPa magnitude; a sensor's original pF is retained as observation provenance when that is its native output.

## Equations and domains

For a finite nonzero signed potential `psi_kpa`:

```
pF = log10(abs(psi_kpa) * 10)
   = log10(abs(psi_kpa)) + 1
abs(psi_kpa) = 10 ** (pF - 1)
```

Implement the second logarithmic expression to avoid overflowing the intermediate multiplication. The inverse returns a magnitude, so it cannot recover the original sign. Both positive and negative finite input potentials have the same pF. Negative pF is valid when the magnitude is below 0.1 kPa.

Zero, including negative zero, has no finite logarithm and returns null. Missing and non-finite inputs return null. An inverse result that overflows or underflows to zero also returns null. Sensor adapters validate their own ranges and sentinels before conversion: taking an absolute value must never turn an invalid sensor code into a measurement. Tensiomark acquisition still accepts only native pF 0 through 7.

This contract uses **hPa**, matching ecoTech's published correspondence of pF 0–7 to 1–10,000,000 hPa. Centimetres of water are a different scale: one conventional centimetre of water is 0.0980665 kPa. Do not substitute that factor in this hPa-convention conversion. Sources: [ecoTech Tensiomark](https://www.ecotech.de/en/product/tensiomark), [NIST SI conversion factors](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9).

## Precision

Keep the exact received pF token, including its sign and trailing zeros, with the original packet and acquisition configuration. Parse a finite number for calculation, compute kPa once on the edge, and retain that double without decimal rounding. The cloud stores the incoming edge value; it does not repeat the exponential calculation.

SQLite REAL and JavaScript/Java double calculations have finite binary precision. Retaining the source token avoids losing the sensor's decimal representation. Do not promise exact real-number results from an exponential: the guarantee is no additional decimal rounding or truncation in acquisition, storage, transport, APIs or raw export.

The accompanying vectors use independently calculated reference values. Mathematical comparisons use absolute or relative tolerance of 2e-14. Transport tests are stricter: the stored and transported double must have identical IEEE754 bits, and the original token must match exactly. SQLite JSON construction is not proof of a round trip; test the actual producer and consumer.

Display strings may use the chosen decimal format. Never parse a formatted display value back into canonical state. Raw CSV preserves round-trippable numbers. For an individual native observation, retained pF is source evidence; pF derived from kPa remains a conversion. For aggregates, aggregate canonical kPa first, then convert. A mean of native pF is not equivalent to pF of mean kPa.

## Compatibility

This contract supersedes the legacy pF floor and four-decimal CSV rule in the SWT section of `../sync-schema/canonicalization.md`. The old document remains the record of that behavior. Payload canonicalization, history hash versions and sensor validity contracts are separate and are not changed by this mathematical contract.

A finite zero-kPa observation remains zero kPa. Its pF representation is unavailable because the logarithm is undefined. Finite nonzero magnitudes below 0.1 kPa now retain their negative pF instead of being collapsed to zero.

## Native observation history

`tensiomark_observations` uses its own history table registration with hash version 1. Existing `device_data` hash versions remain unchanged. Its key is `TENSIOMARK_OBSERVATION|<gateway EUI>|<edge observation ID>`. The cloud owns no new sensor metric for native pF: it stores source evidence in `edge_tensiomark_observations` and checks that the device belongs to the authenticated gateway.

The ordered hash columns are `id`, `device_data_id`, `deveui`, `recorded_at`, `received_at`, `raw_response_hex`, `payload_base64`, `configuration_hash`, `configuration_json`, `disposition`, and `normalized_json`. IDs use the history INTEGER encoding, timestamps use TIMESTAMP, and all other fields use TEXT. Every transmitted field participates in the hash. The source JSON strings remain exact TEXT, preserving token spelling and decimal representations. The original response travels as uppercase byte hex so rejected responses containing NUL can survive PostgreSQL storage. Rejected observations may retain malformed Base64 packet text; accepted observations require canonical Base64 when that field is present.

`device_data_id` is the edge's row ID and may be null after canonical-row retention. It is never a reference to a cloud-local measurement ID. Observation arrival may precede measurement arrival. A repeat with the same hash is a duplicate; a changed source token or normalization produces a history correction. Updates use the observation dirty-key trigger. Reconstructing canonical kPa from retained source uses the ordinary measurement dirty-key correction path, never replacement append events.

Normalization version 2 records `conversion: "matric-potential-hpa-v1"`, a `native_pf` map of channel names to exact source tokens, full-precision `channels`, and `disposition`. Rejected readings have no valid native pF entries. The original packet and acquisition configuration remain available alongside it. See `observation-v1.json` for a paired edge/Java hash and storage fixture.

Deploy cloud support before edge emission. An older cloud that reports `unsupported_table` leaves the new table pending while other history tables continue; it must not discard the observation cursor or block ordinary measurement delivery.
