# Valve commands and conditional watering v1

K3 defines the 0.9 implementation contract for valve commands, run evidence and
conditional watering. Status: **draft, edge-lead sign-off required**. It precedes
EB7a, the EB8–EB10 interface fixtures, EB11a, EB21, CL1 and CL9. A fixture pass is
software evidence; it does not qualify a valve or approve physical pass marks.

## Identity and evidence

A command has a durable command identity and physical-effect identity. Preserve
the existing `command_id`, `effect_key`, `expectation_id`, `schedule_uuid`, policy
UUID/revisions and occurrence decision key through retries and history. A retry
of the same request must not allocate another physical effect. A new farmer
request is a new command; K3 adds no ordinary competing-open exclusion.

UC512 adds an outlet dimension: `(device_eui, valve_index)`, with `valve_index`
1 or 2. Outlet 1 evidence cannot settle outlet 2. This is an EB21 interface
requirement, not an existing field in the STREGA actuation mirror (decision S3).

Store requested action, direction, encoded duration, source, actor and times
separately from observations. Timestamps are UTC instants; weekly schedules also
carry an IANA timezone and local clock time. Missing observations and volume are
`null`. A target state, queue receipt, HTTP success, command ACK or elapsed timer
never substitutes for a position report or flow measurement.

## Outcomes and transitions

Use four independent facts. The lowercase vocabulary in fixtures is a comparison
projection for consumer tests (S1), not a new wire enum or database migration.
Existing raw states must remain available to adapters.

| Fact | Values | Meaning |
| --- | --- | --- |
| Admission | `accepted`, `refused` | Accepted means the named layer validated and recorded the request. Refused means that layer did not authorize/start this effect, with a stable reason. Name the layer: cloud, edge or device. |
| Transport | `not_attempted`, `queued`, `handed_off`, `uncertain`, `cancelled` | Queued requires enqueue acceptance or an attributable live queue item. Handed off means the request crossed into transport and cannot be proven removed before delivery. Uncertain means an attempted operation has an unknown result. Cancelled requires the cancellation semantics described below. |
| Observation | `unobserved`, `observed_running`, `observed_complete`, `observed_closed`, `stale_no_observation`, `stale_open_observed` | These describe position evidence and its attribution. “Observed” means a valve report, not proof of water movement or the cause of movement. |
| Schedule settlement | `pending`, `fired`, `missed`, `uncertain`, `skipped`, `cancelled` | Fired means dispatch acceptance or attributed OPEN proof under the once rules. Missed means no enqueue attempt occurred before the due opportunity expired. Uncertain means enqueue was attempted but not confirmed. Skipped records an intentional decision with reason. Schedule cancellation prevents future dispatch; it does not retract a frame already handed off. |

An outcome must include its evidence level and reason. Distinguish refusal from a
failed attempt: a timeout after enqueue begins is uncertain, never “refused,
therefore no watering”. A cloud `202 PENDING` proves only cloud acceptance. Edge
`applied`/`already-applied` proves application at the edge boundary specified by
that command, not physical actuation. `REJECTED_PERMANENT` is a durable refusal;
retryable failures retain their reason and attempt evidence.

The baseline local open reply is 202 `status: queued`,
`transportPhase: ACCEPTED`, with nullable `queue_id`. Enqueue rejection maps to
422; an unknown transport result maps to 503 and remains uncertain. A persistence
failure after possible enqueue is also uncertain even when the HTTP reply is
503. Never infer non-delivery from the status code alone.

Allowed progress, with evidence retained:

| From | Event | To or retained fact |
| --- | --- | --- |
| New request | Invalid duration/action, missing target, unsupported hardware, denied/revoked authority, stale revision or missing capability | Refused at that layer; no new physical enqueue |
| Accepted locally | Enqueue not yet begun | `not_attempted`; reservation alone is not a receipt |
| Accepted | Positive enqueue receipt or uniquely owned live queue match | `queued`; observation remains `unobserved` |
| Enqueue attempted | Lost reply, process interruption, malformed receipt or unavailable persistence after possible acceptance | `uncertain`; retain identity, do not blindly resend |
| Queued or uncertain | Queue absence, a cancel read/flush race, or possible radio handoff | `handed_off` or remain `uncertain`; absence proves neither delivery nor failure |
| Any attempted transport state | Fresh attributable OPEN | `observed_running`; retain the original transport result and attribution limits |
| Observed running | Fresh attributable CLOSED after OPEN | `observed_complete`; preserve both report times |
| Close command | Fresh attributable CLOSED | `observed_closed`; no invented OPEN or watering duration |
| Pending observation | Observation deadline + grace elapsed | `stale_no_observation`; command may still arrive later |
| Observed running | Observation deadline + grace elapsed without CLOSED | `stale_open_observed`; final closure is unknown |
| Never-attempted once opportunity | Due grace/cutoff exceeded | `missed`; no watering event claiming execution |
| Attempted once opportunity | Confirmation deadline exceeded without qualifying proof | Schedule `uncertain`; this neither expires nor cancels its frame |
| Pending schedule/policy | Disabled, deleted, paused, below threshold, missing evidence, scope lost or other guard | No new dispatch for that opportunity; preserve reason and any earlier attempted effect |
| Settled uncertain once | Eligible late OPEN proof within correction window | One correction to `fired`; original SKIP remains, no second enqueue |

Duplicate/reordered reports cannot regress a newer observation or create a second
run. If attribution fails, record an unexplained physical run rather than credit
an arbitrary command. A device-local/magnet open may be indistinguishable from a
commanded open; report that limit. Do not label it “command delivered”.

### Mapping the expectation table

`valve_actuation_expectations.reconciliation_state` is baseline evidence, not a
delivery state machine:

| Raw state | Contract interpretation |
| --- | --- |
| `PENDING_OBSERVATION` | An expectation exists; neither execution nor delivery is proven |
| `OBSERVED_RUNNING` | OPEN was attributed; stop is unconfirmed |
| `OBSERVED_COMPLETE` | OPEN and later CLOSED were attributed |
| `OBSERVED_CLOSED` | CLOSED settled a close owner; it proves no preceding watering |
| `STALE_NO_OBSERVATION` | No attributed OPEN by the monitor deadline; use uncertain/unobserved wording, never “definitely missed” |
| `STALE_OPEN_OBSERVED` | OPEN was observed; no attributed final CLOSED by the monitor deadline |
| `CANCELLED` | Local cancellation bookkeeping; inspect the cancel path and proof before describing non-execution |

The baseline monitor uses `effect_snapshot.future_effect_end`, or a legacy timed
row's `expected_close_at` when it has no transport phase, plus 1,800 seconds.
Rows without a usable deadline do not become stale merely by age. Report-only
expectations (`command_id: null`, duration sentinel) are physical-run records,
not pending timed commands. Some are local-only under the current v1 projection;
EB9/CL1 must agree a projection before claiming cloud parity for them.

### Cancellation

STREGA cancellation deletes pending work. It sends no new CLOSE and never ends an
already-open valve's run. Normal watering ends on the valve timer. Explicit
emergency close is a separate, confirmed recovery action, with its own delivery
and CLOSED evidence. This distinction applies to tests and cleanup too.

Baseline routes are `POST /api/v1/valves/:deveui/cancel` and local alias
`POST /api/valve/:deveui/cancel`; cloud uses `CANCEL_VALVE_ACTUATION` through REST
pending commands. An optional `expectation_id` identifies the active positive-
duration non-report-only target. Unknown/no target gives 404 `no_active_actuation`;
an inactive named target gives 409 `actuation_not_active`. With several candidates
and no ID, select only the single candidate whose stored queue ID is still
unsent. Otherwise return 409 `ambiguous_actuation`, with `ambiguity` one of
`none_queued`, `several_queued`, `queue_unreadable`, `conditional_irrigation`.
Never choose the newest by default.

| Baseline path/result | HTTP / raw fields | Required interpretation |
| --- | --- | --- |
| Ordinary read/remove/refill succeeds | 200 `status: cancelled`, `outcome: cancelled`, `confirmation: queue_flushed`, expectation becomes `CANCELLED` | Queue cancellation was recorded. A fetched frame can still run. This is not proof of non-delivery or closure. |
| Conditional/whole-queue path proves never enqueued | 200 `outcome: cancelled`, `pending: false` internally; transport gets an unsent cancellation stamp | Proven stopped before handoff; no new send |
| Conditional target handed to ChirpStack, even if listed unsent before flush | 409 `error: actuation_handed_off`, `outcome: handed_off`; internal `pending: true` | Flush cannot prove the open stopped; expectation remains active |
| Conditional target already `OBSERVED_RUNNING` | 409 `actuation_handed_off`, `outcome: already_running` | Nothing to delete; no flush; valve continues its own run |
| Conditional flush fails or has unknown result | 503 `transport_uncertain`, `outcome: uncertain` | Cancellation pending/uncertain; preserve the active expectation |
| Ordinary queue RPC fails | Failure response; never mark cancellation successful | Preserve attempt evidence; an error alone proves no physical outcome |

The ordinary path requeues retained configuration, plan work and CLOSE frames;
it drops other opens and unbounded moves and reports `dropped_opens`. A read/flush
race can replay retained work. Conditional/unclaim whole-queue flush replays
nothing and returns `collateral`, including other owners and lost plan pushes.
Preserve `queue_scope`, `collateral`, `dropped_opens` and uncertainty through cloud
ACKs and screens. Retrying a cancel uses the same target; it must not silently
cancel a newer run. EB7a/CL1 own any strengthening of ordinary cancel truth (S2).

### Once confirmation

Keep baseline `valve_schedules.once_state` (`PENDING`, `FIRED`, `SKIPPED`) separate
from `valve_once_dispatch_intents.state` (`PENDING`, `ATTEMPTED`, `UNKNOWN`, `SENT`,
`FIRED`, `SKIPPED`). Durable command/effect identity prevents repeat execution
after restart or concurrent ticks. An intent timestamp or snapshot without
transport attempt evidence is not an enqueue attempt.

Baseline due grace is 10 minutes; a preclaim snapshot cutoff may end it sooner.
At exactly 10 minutes, grace alone has not expired; after it, an unattempted
request becomes SKIPPED with `once_settlement: missed` and `one_time_missed`.
Attempted requests instead await confirmation until the persisted deadline:

`attempted_at + clamp(2 × interval_minutes + 5, 15, 180) minutes`.

Estimate interval from the median gaps of up to ten pre-attempt uplinks in the
preceding 48 hours, discarding gaps below 30 seconds. Fewer than two usable gaps
uses 10 minutes. Persist `once_confirm_by` and `once_interval_minutes` once; later
reports or listings cannot slide the deadline. At the deadline it still waits;
afterward it settles uncertain if there is no proof.

Proof precedence is `receipt`, `observed_open`, then uniquely attributable
`queue`. Receipt/queue proof means accepted for dispatch, displayed as Fired;
`observed_open` means “Valve reported open”. Competing commands, unresolved old
opens, service actions and opaque queue owners prevent false attribution. The
worker revalidates schedule eligibility and proof under its writer after RPCs.
Removal proof and read timing must satisfy the existing workers' guards; a queue
absence alone is insufficient.

After uncertain settlement, a qualifying OPEN in
`[attempted_at, confirm_by + encoded duration]` may correct the schedule to FIRED
with `one_time_open_reported_late`. Retain `one_time_uncertain` SKIP and create or
update exactly one IRRIGATE event under either CLOSED/correction ordering. The
intent may remain SKIPPED. Baseline correction scans candidates from the last
24 hours; it offers no correction beyond its evidence window. No correction
enqueues another open. A notification deadline imposes no ordinary queue expiry.

## Devices and farmer actions

### STREGA v1 and v2

`GEN1`/`GEN2` describe controller protocol; `STANDARD`/`MOTORIZED` describe actuator
hardware. Do not derive one from the other. Both generations use bounded
`OPEN_FOR_DURATION` for normal irrigation and close themselves after the encoded
duration, measured from actual opening. A timed open received while STREGA is
already open is ignored: it adds no start and does not extend the original
timer. Only a delivered CLOSE actively ends that run early; cancel does not.

| Farmer action | Baseline interface and bounds | Required state/history |
| --- | --- | --- |
| Timed open | `POST /api/valve/:deveui`, `OPEN_FOR_DURATION`, integer `duration_minutes` 1–255 | Pending until report; requested and encoded duration retained; expected close is an estimate |
| Emergency close | Explicit confirmed override `CLOSE`; cloud `/api/v1/valves/{deviceEui}/close-override` | Separate close request, then reported CLOSED if seen; no cancellation or timed-open label |
| Timed open/close service | `PUT /api/devices/:deveui/strega/timed-action`, `action: OPEN|CLOSE`, `unit: SECONDS|MINUTES|HOURS`, integer `amount` 1–255; local `CLOSE_FOR_DURATION` also exists | Timed CLOSE can return to OPEN after the dry interval. Label initial direction, duration and return state; never describe it as a self-closing open |
| Partial move | `PUT /api/devices/:deveui/strega/partial-opening`, `action: OPEN|CLOSE`, integer `percentage` 1–100 | MOTORIZED only. Record direction and requested percentage; position/flow remain unmeasured unless observed |
| Flush | `PUT /api/devices/:deveui/strega/flushing`, `return_position: OPEN|CLOSE`, integer `percentage` 1–100 | MOTORIZED only. Record excursion and selected final position; returning OPEN can keep water flowing |

These controls remain on farmer screens. Unsupported/unknown models show the
reason and enqueue no partial/flush frame. Baseline cloud
`SET_STREGA_TIMED_ACTION` permits bounded OPEN only, normalizing to whole-minute
`OPEN_FOR_DURATION` (ceiling seconds/60, maximum 255). Local seconds/hours service
encoding is different. CL1 must resolve timed-CLOSE parity explicitly (S4), not
pass a raw payload around the command registry. EB8 records partial OPEN/CLOSE
direction before using those events in once attribution.

### UC512 (EB21)

Full open, close, cancel, schedules, history and a dedicated card are required in
0.9. Baseline has telemetry and codec tests, but local control rejects non-STREGA
devices and cloud `UC512_OPEN_FOR_DURATION` reaches `no_dispatcher_on_gateway`.
Catalog/codec support is not a usable control path.

Required EB21 interface fixtures use outlet 1/2, timed open with positive integer
seconds, explicit close, and cancel of a named queued open. The codec accepts
`encodeValveTask({valve_index, valve_status: 'open'|'close', duration,
sequence_id})`. A close uses duration 0; open without duration is refused.
Sequence IDs are transport correlation, never a durable command/effect identity.

S3 proposes the following complete interface for EB21 to implement after sign-off:

| Interface | Proposed request/result contract |
| --- | --- |
| Edge and cloud `/api/v1/valves/{deviceEui}/outlets/{valveIndex}/open` | POST `{request_id, duration_seconds}`; integer seconds 1–15300 (255 minutes); 202 pending/queued receipt with command identity, outlet and expectation identity when known |
| Same prefix `/close` | POST `{request_id}`; explicit physical CLOSE, encoded duration 0; 202 receipt, observation stays unconfirmed |
| Same prefix `/cancel` | POST `{request_id, expectation_id}`; named queued open only; 200 proven cancelled, 409 handed_off/already_running/inactive, 404 unknown, 503 uncertain; return outlet and collateral |
| Same prefix `/schedules` and `/schedules/{scheduleUuid}` | GET list, POST create, PUT edit, DELETE disable/tombstone. WEEKLY 1–240 whole minutes, ONCE 1–255; UUID, expected version, local time/zone or absolute fire time as above. Cloud writes stay pending |
| Pending commands | Extend `UC512_OPEN_FOR_DURATION` with required `valve_index`; add `UC512_CLOSE` with `valve_index`. Extend `CANCEL_VALVE_ACTUATION`, `UPSERT_VALVE_SCHEDULE`, `DELETE_VALVE_SCHEDULE` with required outlet for UC512. Keep command/effect identity and authenticated actor context |
| Execution and history | Edge executes weekly/once opportunities using durable per-outlet occurrence identities; no UC512 onboard schedule assumption. Actuation/runtime/history projections include outlet; device-wide queue changes serialize on device EUI and report all outlet collateral |

These route names and command extensions are proposals, not registered wire
support. EB21 must update the existing schemas, registry, appliers and cloud
mirrors together, with capability gating, before a producer sends them. The
codec's 24-bit duration capacity does not authorize a longer farmer request.

Cancel is queue removal; close is a physical command with observed closure.
Cancel-after-handoff must disclose that watering can continue. Scope cancellation
and history to the outlet; a device-wide queue flush must disclose collateral on
the other outlet. Preserve weekly and once semantics below. Capability claims
must describe implemented, qualified actions; do not expose service partial/flush
controls by borrowing STREGA's model. Bench proof must establish UC512's behavior
on a second open while running, including its stop time (S3).

### Decided delivery limits

There is no #655 ordinary-command interlock in 0.9. Ordinary manual, daily
scheduler, cloud and once commands are not refused solely because an earlier
ordinary command exists. A last-reported OPEN warning must be visible and dated;
it is not current physical certainty. Late ordinary opens may water and still
run their encoded duration. An already-open STREGA ignores another timed open.
Two queued opens can nevertheless run separately if the second arrives after
the first closes, including when an intervening report was lost. Do not promise
one physical run across distinct commands or invent a gateway expiry from a UI
deadline. UC512 must meet the same stated product limit with bench evidence.

Conditional watering retains its existing expiry, ownership, qualification and
clear-ACK guards. Excluding #655 does not remove these conditional guards.

## Schedules, run history and volume (EB8–EB10 interfaces)

Weekly rows use `kind: WEEKLY`, `weekdays_mask` 1–127 (Sunday bit 0), `start_time`
`HH:MM`, `timezone`, duration, enabled flag and stable UUID/revision. STREGA is
capped at four windows per weekday and 1–240 whole minutes per weekly window.
Once uses `kind: ONCE`, absolute `fire_at`, 1–255 whole minutes and the confirmation
rules above. Save/enqueue is not proof that the valve holds a plan. STREGA never
reports its complete onboard schedule; track positive push ACKs, loss, pending
and resend separately. Push on user change or explicit resend, never a periodic
plan-push timer. Existing clock maintenance is a separate operation.

EB10 must preserve local weekday/time on a zone-timezone change; recalculate
future UTC occurrences. Already dated ONCE instants stay fixed (S5). The existing
conditional occurrence resolver skips nonexistent DST times and chooses one
occurrence at an ambiguous time; fixtures pin its choice. Pause/delete suppresses
future opportunities, preserves rows/history and does not assert that a handed-off
run stopped. Conditional conversion cannot leave an independent fixed plan armed.

EB9 must correlate request, expectation, occurrence and observed physical run in
every history surface, preserving source (`manual_local`, `manual_cloud`,
`weekly`, `once`, `daily_swt`, `daily_dendro`, `conditional`, `service`,
`unexplained`) through adapters. These are fixture labels, not a replacement
for existing raw `trigger`/`reason`. A scheduler decision `IRRIGATE` expresses
intent; a downstream refusal must not be displayed as observed watering.
Uncertain SKIP and its late correction are one opportunity, not two runs.

Keep `estimated_gross_liters`/`volume_source` separate from measured flow. A
measured calibration rate multiplied by commanded minutes is still an estimated
volume. `zone_daily_environment.flow_liters` is measured flow only. Without a
meter or valid calibration, leave the corresponding quantity null. Requested
percentage is not a flow fraction. Rain and soil-response overlays use actual
event times and source provenance; absence of a response is not zero response.

## Conditional-policy shape and eligibility (EB11a/CL9)

The existing conditional schema owns the wire format. Do not create a second
policy wire contract. Full create uses an explicit null `expected_policy_version`;
updates carry the exact current version. Each schedule edit carries
`expected_sync_version` (null for complete creates, integer for edits).

| Policy field | Contract |
| --- | --- |
| `policy_uuid`, `zone_uuid` | Stable policy identity and canonical zone identity; one live policy per zone |
| `condition` | SWT `{kind, threshold_kpa, sources}` or DENDRO `{kind, minimum_stress, response_mode}` for the retained daily path |
| `timezone` | Zone IANA timezone; all member schedules agree |
| `enabled` | Desired activation, subject to authority, peer capability, qualification and edge application |
| `observation_window_minutes` | Integer 1–1440, default 60 |
| `min_interval_minutes` | Integer 0–1440, default 60; enforce with existing occurrence bounds |
| `max_daily_minutes` | Integer 1–1440, default 240; budget across every local day touched by a reserved run |
| `delivery_settings` | Per-valve `delivery_interval_minutes` integer 1–60; existing default 10 |
| `schedules` | Conditional WEEKLY opportunities, enabled flag, local time/day mask, duration 1–240, execution mode and version. Without selected schedules, create daily (mask 127) at the farmer's chosen time |
| `effective_from` | Edge activation boundary; enabling never catches up older opportunities |

Threshold crossing does not immediately water. At a scheduled opportunity SWT
uses positive canonical kPa (`swt_1`/`swt_2`/`swt_3`), threshold `0 < x ≤ 300`.
Wet/Moist/Dry preferences are 20/30/50 kPa; custom values retain precision.
Each selected source must be eligible and have valid evidence in the inclusive
window `[due_at - observation_window, due_at]`. Deduplicate each source by sample
instant, taking the highest row ID, average that source's valid samples, then
average source means equally. Compare `mean >= threshold`; do not round first.
Missing one selected source makes evaluation UNKNOWN, not an average of the rest.
Zero kPa is a valid wet sample; negative, nonfinite and out-of-range samples are
excluded. See [matric potential](../matric-potential/v1.md).

DENDRO uses the daily analysis, no user-selected SWT sources. Minimum stress is
`mild`, `moderate`, `significant` or `severe`; require at least one usable tree,
known action/stress and a nonfuture analysis no older than 36 hours. Compare the
ordered stress ranks. `maintain_recovery_hold` and `maintain_rain_suppression`
skip. Missing/stale/unknown evidence yields UNKNOWN. The retained 0.9 baseline
policy is `response_mode: fixed`; its duration is the selected base duration.
The schema/model also support `proportional` multipliers today; that is not proof
of the planned 2027 controller. S6 requires an explicit decision about exposing
that existing option, without deleting stored configurations.

The legacy daily scheduler stays available until conversion. Its SWT query
aggregates last-hour zone evidence and its DENDRO branch uses a daily
recommendation, optionally a fresh server-preferred bundle. Its DENDRO threshold
column encodes stress 1–4, not kPa; the pinned branch does not enforce that stress
threshold and can dispatch on hold recommendations. It also writes IRRIGATE
alongside the command before downstream acceptance and debounces by UTC date.
These baseline differences are EB11b/EB9 defects to reconcile, not behavior to
copy into the conditional evaluator. The converted path must skip holds and
below-threshold days, and show the conversion preview's change in behavior.

| Input/target | Eligibility rule |
| --- | --- |
| KIWI SWT, including KIWI-read WATERMARK | Eligible declared `swt_1`/`swt_2`, correct zone and valid evidence; the LSN50 interlock does not apply by sensor brand |
| Commissioned Tensiomark | Eligible declared SWT channel from identified/manual SDI-12 layout, correct zone and valid evidence |
| LSN50 Chameleon | Correct zone/channel, enabled reader, calibrated and healthy channel; do not confuse this with LSN50 WATERMARK |
| Any `device_data` row linked to `watermark_readings` (LSN50 WATERMARK) | Excluded by both scheduler and policy evidence selection. Firmware accuracy repair and a drying-cycle reference comparison, followed by a separate approved activation decision, are required to lift it |
| Clover VWC | Separate calibrated capture, conversion/storage and activation decision. Building Clover display support does not make it eligible. Baseline source gate does not admit Clover |
| Other VWC | Existing commissioned SDI-12 sources and disabled-by-default VWC activation gate remain governed by their current contract. K3 does not broaden eligibility |
| DENDRO | Daily measurement fixes accepted on replay and bench reference; 2027 living-tree/proportional-controller claims deferred. Evidence freshness and quality gates still apply |
| Conditional target valve | Correct zone, supported controller/outlet, cleared fixed plan with required positive ACKs, qualified firmware identity and fresh runtime readiness; UC512 joins only after EB21 and TF1 proof |

A MET result alone cannot dispatch. Recheck authority, policy/schedule revisions,
enabled/effective times, clock lower bounds, evidence, min interval, daily budget,
readiness and qualified firmware under the worker's existing serialization.
Clock behind stored evidence refuses/defer dispatch; NTP since boot is not
required. Unknown qualification stays false. Production qualification is false
on the baseline, and fixtures cannot change it.

Conversion clears fixed schedules through the normal push path; wait for every
required clear ACK. An onboard scheduled open while conditional management is
active records an incident and blocks further conditional dispatch. Pause does
not restore a fixed plan. Convert to Always explicitly to restore it; retry-valve
reconciles the incident/readiness, not a past watering command. Pausing may leave
a handed-off run pending until observations settle it.

Conditional occurrence transport states are also separate from position:
`PENDING → CLAIMED → RESERVED → ATTEMPTED → SENT`. PENDING/CLAIMED can become
SKIPPED; RESERVED can become SKIPPED or EXPIRED; ATTEMPTED can become UNKNOWN
or EXPIRED. An ambiguous flush can change SENT to UNKNOWN while retaining the
reservation and acceptance markers. UNKNOWN, SKIPPED and EXPIRED have no ordinary
outgoing state transition. The store's separate proven-pre-acceptance-failure
exception requires command-bound non-delivery evidence; it is not a general
retry permission. Observed OPEN/CLOSED fields advance independently of those
states. Deferred clock/readiness work must not fabricate a completed decision.

## Authority and cloud activation

The sibling [authority contract K1](../authority/v1.md) owns roles, grants,
session revocation and actor identity. It is being written in parallel and was
absent at this source pin. This section states assumptions for K1 review; it
does not grant extra powers.

| Actor/scope | Manual open/cancel/confirmed override | Schedule/policy change |
| --- | --- | --- |
| Current owner/admin within K1's installation scope | Allowed when K1 authorizes the target | Allowed when K1 grants zone management |
| Enabled member granted this zone with valve-operation permission | Same valve operations on gateway and cloud, per owner decision #451 | Require K1 zone-management permission; operation permission alone is insufficient (S7) |
| Read-only viewer, no grant, disabled/revoked actor, foreign zone/gateway | Refuse | Refuse |
| Internal due worker | Only a currently authorized, enabled policy/schedule in the same zone; recheck scope | Cannot confer grants or bypass activation |

All mutation entry points, including service controls, UC512 outlets and cloud
apply, must recheck current authority before the effect. Actor identity comes
from the authenticated service context, never from a farmer-controlled field.
Cloud forwards `actor_user_uuid` in the pending envelope. Permission at cloud
queue time is not permission at edge apply time. Cross-valve schedule UUIDs and
foreign expectation IDs cannot authorize mutation. K3 confers no fan/reboot
authority; those are owner/admin only under K1.

Edge policy routes are `/api/irrigation-zones/:id/irrigation-policy` with `pause`,
`retry-valve`, `decisions`; cloud uses
`/api/v1/irrigation-zones/by-uuid/{zoneUuid}/irrigation-policy`. CL9 activation
uses `UPSERT_IRRIGATION_POLICY`; stopping uses `PAUSE_IRRIGATION_POLICY`, and
incident retry uses `RETRY_IRRIGATION_VALVE`. Both peers must confirm
`conditional_irrigation_v1`. Unknown/unsupported peers get no conditional rows
and no fallback to legacy saves. REST pending commands are the sole cloud-to-edge
path; MQTT carries edge telemetry/status/ACK only.

Cloud `202` displays a pending edit while confirmed policy remains unchanged.
Settle an applied edit only after authoritative edge ACK and matching mirror
convergence, in either order. A definitive non-application rejection settles
without convergence; timeout/disconnect retains pending/unknown truth. Replays
of identical `request_id`/effect identity create no second edit; changed payload
under that identity conflicts. Edge revalidates versions, sources and qualification.

Pause is a stop request with explicit nullable `expected_policy_version`; the
baseline cloud deliberately emits null to pause the current version. While the
first create is unanswered, withdraw it only if proven undelivered; otherwise
queue a durable pause intent behind it. A queued pause must survive disconnect
and apply to the created policy, while edge authority rules still hold (S7).
Pause is not physical closure. Do not mark a cloud enabled policy as ready to
water from a stale runtime projection (baseline freshness capped at 7 minutes).

## Fixture protocol and consumer obligations

[MANIFEST.json](MANIFEST.json) lists every fixture and its consumers. Every suite
has `contract_version: 1`, a `suite` name and `cases`. Each case has a unique `id`,
`basis: baseline|requirement|proposed`, `check`, `input` and `expected`. `decision` names
a pending sign-off when relevant. Inputs are synthetic domain scenarios unless
an `envelope` or an explicitly named function input says otherwise. Expected
fields are exact assertions for those fields; omitted fields are unconstrained,
not null. `null` is asserted absence. Consumers adapt their real responses to
this projection and assert expected fields recursively, preserving array order.
They must execute actions/events in supplied order and test retries/restarts.
Do not implement a second watering engine by replaying these JSON files.
