# Refuse image upgrades that can erase a provisioned gateway

Implement the CTO's option (1). Owner approval and independent review remain merge gates. A persistent state partition is a later project. No boot migration or payload-switch code changes belong here.

## Startup and delivery order

The source guard is installed by this PR's additive `deploy.sh` step beside the Node-RED init installation. It wraps the installed `/sbin/sysupgrade` and `/usr/libexec/validate_firmware_image`, preserving each stock implementation beside its wrapper. CLI, LuCI file execution and rpcd upgrade calls reach the first wrapper. Direct procd `system sysupgrade` reaches the second before stopping services, including forced calls. The source guard rejects a database with accounts, unreadable/unprovable database state, or ChirpStack state. Read-only help/list operations remain available. Root can deliberately remove the guard or invoke a stock implementation; that is outside the supported entry points.

An image-owned required marker enables destination initialization. Application deploy does not install that marker, so older images continue their normal application deploy path. The destination check runs before DB seeding, before code copying and at the beginning of Node-RED startup. It must run before W5's repair-at-boot: retained code and DBs are evidence for refusal and must not be changed by payload recovery first. Bootstrap must also respect the hold.

## Implementation sequence

1. Add `scripts/test-image-upgrade-safety.js` to exercise the real seed scripts, installed wrappers, init start functions and HTTP hold responder against temporary directories. First run on the campaign base proves kept state currently seeds or starts instead of holding. Keep this failure log outside the repository. Tests use synthetic SQLite data and stock-script sentinels; never invoke real upgrade/reset commands.
2. Add `files/usr/libexec/osi-image-safety.js` to both maintained profiles. Export fixture-root operations; the production CLI always uses `/`. Provide source guard, idempotent wrapper installation, first-boot preparation/seeding, ready check and failure recording. Store a bounded atomic JSON status at `/etc/osi-image-initialization.json`. Any retained DB, sidecar, ChirpStack state or old application on the first image boot causes a permanent hold. A recorded fresh initialization can resume; only complete seeding/code initialization marks ready. Missing state after ready causes a hold, never a reseed.
3. Add `files/etc/osi-image-initialization.required` and a read-only Node HTTP hold responder. The Node-RED init starts that responder instead of the application while held. The responder serves a plain explanation at the GUI address and accepts no recovery writes. Missing safety code with a required marker refuses application startup.
4. Make script 97 delegate guarded atomic fresh seeding. Make script 98 check the hold before touching code, record its failing step on exit, repair only image helper-directory/symlink collisions on a proven fresh initialization, and mark ready only at its end. Hold takes precedence over W5 recovery. Existing module and native sqlite validation remains.
5. Install the safety helper/wrappers and console-only `osi-factory-reset --erase-farm-and-radio-state` through deploy and the image defaults. Reset uses OpenWrt's full overlay reset and reboot, clearing farm and ChirpStack state together; it cannot be invoked by the unauthenticated hold page. Require root and a terminal, print the erasure warning, and reject ambiguous flags. No image upgrade bypass flag is introduced.
6. Extend profile parity and CI coverage. Document source entry points, stock-script bypass limits, old-image exposure, verified off-device backup and recovery procedure. Replace runbook implications that sysupgrade is a supported farm upgrade. Add a one-page requirements document for persistent storage and field transition.

## Builder acceptance

For both older fixture images, installing the application guard must make CLI, LuCI/rpcd and direct procd image upgrades refuse before collection or service shutdown. Without the guard, the destination must hold on retained ChirpStack/old code, with or without a farm DB. A retained head-70 or head-79 DB stays byte-identical, unqueried by application code and unmigrated. Registration never serves, the GUI explains recovery, and manual starts/reboots preserve the hold. The fresh control still seeds the image head, completes defaults and permits the first account. Reset requires the console and removes both farm and radio state. Power-cut durability and actual image qualification remain the builder's evidence.
